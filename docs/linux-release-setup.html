Linux release setup

Configure the Snap Store and Arch User Repository (AUR) publishers for Agent Terminal.

Keep credentials private. Do not paste them into issues, pull requests, terminal screenshots, or this repository. The Snap and AUR workflows remain disabled until you enable their repository variables.

1. How the release works

  1. Merge the release workflows into the repository’s default branch. GitHub runs release-published workflows from that branch.
  2. Set the matching version in the desktop package, Tauri configuration, and Rust package. Push the corresponding vX.Y.Z tag.
  3. GitHub Actions builds the Linux and macOS artifacts and creates a draft release. Review and test the artifacts before publishing the draft.
  4. When a stable release is published, the separate Linux publishing workflow runs enabled publishers. Prereleases are excluded.

Installation after successful publication: yay -S agent-terminal-bin and sudo snap install agent-terminal --classic.

2. Register the Snap and request classic confinement

  1. Sign in to the Snap Store with the intended publisher account and register agent-terminal. The name must be available to that account.
  2. Request classic confinement approval, explaining that the terminal must run host shells and tools and access project files. Wait for Store approval before enabling publishing.
  3. Install Snapcraft, sign in locally with snapcraft login, and export a credential restricted to this package and stable channel:
snapcraft export-login --snaps=agent-terminal --channels=stable \
  --acls=package_access,package_push,package_update,package_release \
  snap-login.txt

Add the entire contents of snap-login.txt to the repository secret SNAPCRAFT_STORE_CREDENTIALS. For GitHub CLI, from a secure local shell:

gh secret set SNAPCRAFT_STORE_CREDENTIALS --repo OWNER/REPO < snap-login.txt

Replace OWNER/REPO with the repository that will run the workflow. Store or delete the local credential file securely according to your policy.

3. Set up the AUR account and SSH key

  1. Create or sign in to your AUR account. Confirm you are allowed to create or maintain agent-terminal-bin. The -bin package consumes the published Debian release asset.
  2. Generate a dedicated key locally. The following command creates a private key and a matching .pub file; choose a secure passphrase policy compatible with unattended CI.
ssh-keygen -t ed25519 -f ~/.ssh/agent-terminal-aur -C "agent-terminal-aur"
  1. Add the contents of ~/.ssh/agent-terminal-aur.pub to your AUR account’s SSH public keys. Never upload the private key to AUR.
  2. Obtain the AUR SSH host keys and independently verify their fingerprints against the official AUR authentication documentation. Save the verified known_hosts entries in a local file. Do not trust an unverified ssh-keyscan result.
  3. Add the private key as AUR_SSH_PRIVATE_KEY and the verified host-key entries as AUR_KNOWN_HOSTS. The workflow expects a key usable non-interactively; it does not prompt for a passphrase.
gh secret set AUR_SSH_PRIVATE_KEY --repo OWNER/REPO < ~/.ssh/agent-terminal-aur
gh secret set AUR_KNOWN_HOSTS --repo OWNER/REPO < /path/to/verified-aur-known-hosts

4. Configure GitHub Actions

In GitHub, open repository → Settings → Secrets and variables → Actions. Under Secrets, choose New repository secret for each value. Under Variables, choose New repository variable. Configure these in the repository that owns the release, not automatically in your fork.

TypeNameValue
SecretSNAPCRAFT_STORE_CREDENTIALSContents of the restricted exported Snapcraft login.
SecretAUR_SSH_PRIVATE_KEYThe dedicated AUR private key.
SecretAUR_KNOWN_HOSTSIndependently verified AUR host-key entries.
VariableAUR_MAINTAINERPublic maintainer name used in the package and Git commit.
VariableAUR_GIT_EMAILPublic email for AUR Git commits.
VariablePUBLISH_SNAPSet to true only after Snap testing and Store approval.
VariablePUBLISH_AURSet to true only after AUR account and key setup.

The workflow uses GitHub’s built-in GITHUB_TOKEN for downloading release assets; no personal access token is required. Existing macOS signing secrets remain required by the macOS jobs.

5. Validate and publish

  1. Run the Linux build and inspect its AppImage, Debian, and RPM artifacts. Review the draft release’s Linux artifacts and Snap.
  2. On a test Ubuntu system, install the generated Snap with sudo snap install --dangerous --classic ./agent-terminal_*.snap. Check desktop launch, shell startup, host commands, Codex, project access, and notifications.
  3. Confirm AUR package ownership, the verified SSH host key, and both AUR author variables. Review the generated PKGBUILD and checksums.
  4. Enable only the configured publishers. Publish the reviewed stable GitHub release, then inspect Actions → Publish Linux packages. Retry a failed job after correcting its configuration.
  5. After publication, test installation from the Store and AUR on separate machines. Keep the previous version available for rollback.

The Snap build and Store publication require end-to-end validation. Classic approval is controlled by the Snap Store; installing an unapproved local build does not grant Store approval.
